## 2.1.20 UUID request attribution

- ChatGPT connector calls can now arrive with plain UUID request IDs as well as the older `wfr_*` shape.
- The passive SSE/WebSocket observer accepts both through the same bounded opaque request-id contract used by MCP ingress.
- Ownership still requires exact structured server metadata joined to one concrete conversation; model text, tool arguments and malformed IDs are not evidence.
- This restores early attribution when the page-model helper is temporarily empty, preventing an avoidable first-call identity hold when the provider stream already exposes the exact request/conversation pair.
