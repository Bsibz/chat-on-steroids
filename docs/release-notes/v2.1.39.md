## 2.1.39 Stable local macOS identity

- Local macOS dogfood builds now use the owner's existing Apple Development identity with a Team-bound designated requirement.
- Public macOS artifacts remain ad-hoc sealed and unnotarized; the verified local publisher signs and archives a separate temporary copy only.
- Local update manifests carry Team ID, signing identifier, and designated requirement. The updater verifies those fields before replacement and again after the installed bundle is swapped.
- This gives Accessibility and Screen Recording a rebuild-stable app identity instead of a per-build CDHash, so future verified local updates should preserve macOS privacy grants.

The first move from an ad-hoc install to this development identity may need one fresh privacy grant.
